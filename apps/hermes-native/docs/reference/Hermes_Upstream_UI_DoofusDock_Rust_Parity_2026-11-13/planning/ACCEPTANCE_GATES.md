# Release and parity acceptance gate

1. Hermes source version pinned and current; full screen/interaction capture coverage.
2. Exact upstream Advanced layout (and Simple/Advanced preference behavior) verified in native Rust.
3. Every stock Hermes Desktop P0/P1 capability functional with positive/negative path evidence; remaining inventory reconciled and clearly marked.
4. Original source route/menu/hover/keyboard/accessibility/native window behavior verified on Windows.
5. Original upstream profiles work and preserve session/PTY state.
6. Codex/Antigravity/IDE/Doofus-inspired alternate profiles only introduced after original UI parity gate; Morph retarget, preserve active widgets, full return to source identical.
7. No Doofus Hermes bridge/module/plugin dependency; preserve upstream Python agent and working rollback.
8. User approves unresolved stock UI discrepancies before a release is described as a 1:1 replacement.

A successful code compilation is **not** a parity signoff. A close-looking screenshot with different behavior is **not** functional parity. No evidence is recorded until implementation/review occurs.
