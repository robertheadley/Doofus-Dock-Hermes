# Hermes Native architecture and ownership

This document applies the Hermes-specific parts of the supplied Doofus Apps Agent Control and Development Architecture. It does not expand this task into implementation work on Doofus Image, Doofus Code, DoofusDock itself, or unrelated apps. No AI model is embedded in Hermes Native.

## Ownership

- **Hermes Python gateway:** authoritative session execution, backend requests, approvals, recovery and backend events. Rust must not recreate agent logic.
- **Hermes Native app core:** owns navigation and view-specific state; feature mutations use the same approved Hermes gateway methods as source UI.
- **egui/eframe host:** owns rendered widgets, accessibility integration and native windows. Hermes Native remains a standalone app when development control is disabled.
- **DoofusDock:** owns canonical `LayoutDocument`, revision-checked layout changes, profiles and presentation. App owns panel content. Logical layout acceptance and physical OS behavior are separate evidence.
- **Semantic control service (in progress):** the initial typed app-action registry is shared by human route/layout controls and the agent protocol; remaining actions, permissions, and feature-level DoofusDock/Hermes operations are still open.
- **Development Debug Bridge (planned):** authenticated local transport for bounded state, semantic actions, events and diagnostics. It is distinct from Hermes gateway and disabled/absent in production.
- **Development supervisor (planned):** declarative reload, Rust rebuild/restart, generation/readiness handshake and automation-client recovery.

## Current boundaries

`src/layout.rs` owns a `DockingService` and `LayoutStore`; projected panel geometry is rendered through DoofusDock presentation APIs. The UI manually renders projected rectangles and accepts titlebar/tab drags that center-tab or edge-split through revision-checked DoofusDock transactions. Center-docked groups render a switchable accessible tab strip, and the headless agent protocol emits bounded primary/secondary pointer and mouse-wheel events through the same egui draw path, and the headless text-field fill uses AccessKit SetValue. The exact pinned egui renderer is vendored with its license and receives a backward-compatible context-menu callback extension; Hermes session tabs map Pin/Unpin and close/bulk-close actions to session/profile-aware app handlers and canonical Dock transactions. Same-group tab reorder uses a revision-checked `ReorderPanel`; source-aligned Ctrl+Tab/Ctrl+Shift+Tab and Ctrl+PageDown/PageUp select profile-scoped main tabs through hover/focus/workspace precedence and canonical `SelectTab`. New sessions append to the existing workspace tab group, and opening a session flattens legacy nested session tabs through canonical `TabPanel` transactions. Split dividers use DoofusDock resize handles and revision-checked `ResizeSplit` transactions. Floating/cross-window behavior and native window lifecycle remain incomplete. `src/gateway.rs` owns the Hermes transport. It restores existing sessions, creates a fresh session, submits its initial prompt using the runtime session ID, and forwards basic message lifecycle/delta events. Full-history search uses a separate bounded worker with a profile-scoped native HTTP ticket, keeping it off the WebSocket event actor; requests are loopback-only and disable ambient proxies and redirects. `src/app.rs` owns UI and route state, including stored-session navigation, 200 ms session-search debounce/request fencing, ranked full-history result mapping with loaded local matches, compact `last_active` display and the active runtime ID used to fence incoming events. The active composer exposes a Stop action that calls `session.interrupt` with the active runtime session ID; correlated success preserves partial assistant text and marks it terminal, while an already-idle receipt unblocks the composer. `approval.request` events render accessible cards with only backend-offered once/session/always/deny decisions; `approval.respond` carries the active runtime session and execution generation. Single-question `clarify.request` events render source choices, free text, multi-select answers and skip; `clarify.respond` carries the prompt's active runtime session and generation. Batch server-request `clarify` cards stage all question answers, restore replay answers as editable controls, and send sequential `clarify.lock` RPCs in source order; Skip returns an empty server-request result. Both prompt flows validate correlated receipts and disable controls while offline or pending; local fixtures cover scope, mismatched receipts, stale actions and accessible offline state. Live gateway behavior is unverified. Remaining chat gaps include full source create options/retry, other server-request methods and in-flight request multiplexing, complete event reconciliation, idempotent submit recovery and reconnect. The opt-in `agent-automation` feature builds `hermes-automation`, a headless egui_kittest harness around the same `HermesNativeApp::draw` path. It disables gateway startup, uses an isolated temporary layout profile for success and fallback paths, and removes that profile on exit. This proves semantic widget input and headless frame capture for current UI code, but bypasses the OS windowing host. The default build excludes the runner and its renderer dependency.

The sidebar session-list refresh follows the fixed Hermes snapshot's Desktop `/api/sessions` contract and obtains `last_active` through a fresh native HTTP ticket. It keeps the initial authenticated Gateway `session.list` rows as fallback and carries forward any Gateway-only row after the HTTP result, so a session created during refresh is not discarded. The target source revision is fixed at `8783054ef6cbafd86f10892241436862c1171a66`; implementation batches do not follow later upstream commits.

The session row menu supports Pin/Unpin, persisted unread state, and Archive. These writes share the source's `/mutation-snapshot` compare-and-set contract: read the current revision/generation, mint a separate ticket for PATCH, include the mutation request ID and profile, then update UI state only after a positive receipt. Archive also clears `pinned`; a successful archive moves the row out of active sessions. The archived view pages `/api/profiles/sessions?profile=all&archived=only`, preserves profile ownership when IDs collide, and offers profile-scoped fenced Unarchive. Foreign-profile rows cannot open until the chat lifecycle can carry profile scope across resume, prompt, interrupt and prompt responses. Remote connection aggregation, transient unread events, rename and delete remain open.

## Planned control path

`external agent -> authenticated local bridge -> semantic control service -> app handler -> Hermes gateway or DoofusDock transaction -> structured event/receipt -> screenshot/evidence`.

The current chat event renderer also upserts `tool.start` and `tool.complete` events into transcript groups keyed by tool ID and execution generation. It preserves start arguments and displays bounded completion fields; each row exposes its combined speaker and body through an AccessKit group label. This remains a fixture-backed event slice. It does not yet reconcile out-of-order replay or provide the full upstream tool/reasoning card interactions.

The WebSocket reader recognizes server→client JSON-RPC request frames and returns the upstream `-32601` method-not-found response for methods without handlers, including while another RPC is pending; the original RPC continues. `client.capabilities.server_requests` remains false until the UI can receive, surface and answer supported prompt requests. The fallback does not count as interactive server-request support.

For idle inbound `approval` requests, the actor forwards the request ID and params to the app event loop. The app scopes the card to the uniquely matching runtime/profile session pane, renders only supported backend choices, and returns the selected `{choice}` as the JSON-RPC result on that same request ID. The prompt retains its profile so a response can be sent while another pane is active. Requests without a unique owner are declined. The local actor and AccessKit fixtures cover approval and batch clarify routing, with a separate RPC fixture for ordered `clarify.lock` receipts. Active-session ownership across windows and other server-request methods remain open, so capability negotiation stays disabled.

Session-resume commands carry a generated request ID plus stored session ID and profile. The actor echoes that owner tuple in `SessionResumed`; the UI applies a result only when the same profile-scoped cached view still owns that pending request. Success validates the returned session/profile before hydration; errors latch to that view and expose Retry. Disconnect clears pending ownership, while reconnect allows a fresh resume. Authenticated live recovery, authoritative not-found handling and multiwindow ownership remain open.

Read-only diagnostics have narrower scope than mutating actions. Every mutation validates schema, actor, permission, expected state/layout revision and idempotency key. Asynchronous acceptance is not success; report terminal outcomes. The bridge must not be an arbitrary shell/filesystem proxy or bypass Hermes approval.

## Security and lifecycle

Development control is loopback-only with an unpredictable token or equivalently protected local transport. Authenticate writes, bound schemas/payloads, redact sensitive values, audit decisions, support revocation and keep the feature out of production packages. A supervisor should retain the last working build where possible, report failed builds, prevent stale clients from targeting an old process generation, reconnect to the existing Hermes gateway, and never duplicate active submissions. State survival must be explicit by category; do not claim process-local state survives restart without evidence.

## Evidence layers

1. **Core/protocol contracts:** schemas, permissions, persistence, gateway correlation/idempotency and error paths.
2. **Semantic UI integration:** app UI/control service, accessible queries, user-equivalent actions, receipts and headless screenshots.
3. **Physical Windows host:** actual executable, focus, keyboard/IME, native window moves, docking, DPI, multi-monitor and screenshot parity.

Headless screenshots or accepted commands are not physical-host evidence. Visual and functional parity are tracked separately; both are required.

## Current route parity slice: Capabilities

The Capabilities page uses the upstream tab names and keeps `?tab=skills|plugins|connectors|toolsets` in route state. Skills and Toolsets inventories are read through the upstream loopback endpoints `/api/skills` and `/api/tools/toolsets`, each with its own one-use, profile-scoped `native-http` ticket. Requests run on the bounded HTTP worker, with body limits and errors surfaced in the UI. Search is local to the loaded collection. Toolsets can be enabled or disabled through `PUT /api/tools/toolsets/{name}` using a fresh scoped ticket; the row toggle and typed agent action share a handler. The app updates optimistically, validates the server's `{ok,name,enabled}` receipt, and rolls back on failure. The worker processes accepted HTTP commands FIFO. The Plugins tab fetches the pinned Desktop public catalog URL (`https://nousresearch.github.io/hermes-agent/docs/api/plugins.json`) through a single background worker with no credentials, a 60-second request deadline, redirect bound, 32 MiB body cap and 20,000-row cap. Its parser follows the source entry/search fields, display-name fallback and tier+identifier deduplication. The installed Agent Plugin inventory uses profile-scoped `plugins.manage` list/toggle calls on the serialized gateway actor; typed DTOs include source status/update and linked server summaries. Source hidden built-ins are filtered, eligible toggles use the canonical key, and correlated success applies only the returned row for that key while gateway reload/restart outcome is surfaced. A typed UI app action backs both the checkbox and agent protocol; list/toggle counts and errors are bounded in diagnostics. The offline AccessKit fixture uses synthetic installed metadata; no installed profile was touched. Catalog search, selectable details, repository links and refresh remain separate from installed state. Reviewed catalog installs inspect the source, display its full SHA and warnings, require confirmation, and send that SHA with catalog name and profile to the backend; the install receipt is profile- and request-correlated. The view renders 60 catalog rows per page; a live isolated agent UI fetch loaded 2,378 catalog rows in 604 ms without a gateway. The Connectors tab issues the pinned Desktop's read-only `connectors.list`, `connectors.catalog`, and `connectors.accounts` requests on the current serialized gateway actor, then decodes a typed profile-bound snapshot. Request IDs and active-tab checks reject stale results; the directory unions catalog entries with live list slugs, applies source title/status fallbacks, and exposes account aliases/status, source-state segments and source-scoped name/slug search. State groups follow connected, available, off order, with failed/expired attention states first inside the connected group and account ownership/status prioritized like the source join. Isolated WebSocket and AccessKit fixtures cover the read contract and directory behavior; no live profile is used. Connector sign-in, local MCP/plugin server reconciliation, tools and policy editing, hosted-account operations and most card/dialog workflows remain incomplete. Desktop plugin halves/runtime/settings, catalog update/scan-force/custom-repository flows, Windows script fallbacks, and source-paired visual comparison remain open.

Agent Plugin uninstall is limited to `user` and `git` sources present in the profile inventory. The UI and agent semantic action first open the same confirmation window; only its affirmative control submits a profile-scoped `plugins.manage` remove request. Request ID, plugin name and profile fence the result. A confirmed removal invalidates and reloads the inventory; disconnect clears the pending mutation and reports the outcome as unknown.

The public plugin feed and profile inventory are merged by catalog name: matched entries inherit the canonical installed key, source/version/update metadata, and search terms; installed-only rows are appended. The catalog exposes trust-tier, category, tag, installed-only and update-only filters. Tier/category facets combine with AND across groups and OR within a group; tags combine with OR. Tiers normalize to Official, Verified and Community, category chips sort alphabetically with Other last, selected tags remain visible beyond the common-tag limit, and clearing filters resets query and page size. Stars retains the source feed order; Newest and Recently updated sort by their source date fields when those fields exist. Bounded diagnostics expose selected filter counts and sort state.

Agent Plugin uninstall is restricted to `user` and `git` rows in the loaded profile inventory. The Uninstall button and registered agent action both open the same accessible confirmation; confirmation rechecks profile and source before sending `plugins.manage` with `action=remove`, name and profile. Results are request/name/profile correlated. Success invalidates and reloads the inventory, while disconnect clears the pending request and marks its outcome unknown.

Curated Agent Plugin installation begins with profile-scoped `plugins.manage` inspection, then presents the repository, full reviewed commit, component types and backend warnings in a confirmation window. Install sends the selected `catalog_name`, identifier, profile and inspected SHA together; backend commit-movement/security checks remain authoritative. The receipt must match request, catalog entry and profile before the UI clears the dialog and refreshes inventory. Disconnect after admission is an unknown outcome and is never auto-replayed. This path currently installs only the Agent half; Desktop-half reconciliation, scan findings/force review, update and custom repository workflows remain open.

An installed Agent Plugin with `update_available` exposes a profile-bound update button and shared agent action. `plugins.manage action=update` responses can open a capability-delta consent review or a security-scan review. Consent retries carry `accept_capabilities`; only a `caution` verdict enables the explicit `force` override, and `dangerous` remains blocked. Findings are severity-sorted and capped at eight visible lines. The pending result is fenced by request, plugin name, profile and override flags; success invalidates and refreshes the inventory. Profile-scoped Update all is implemented on an isolated authenticated connection. Desktop-half package reconciliation and live update acceptance remain open.

## Files panel

`files::FileBrowserState` owns transient presentation state: selected root, expanded paths, loaded directory entries, errors, selected row, and the active ignored-file filter. The root is derived from the active route's matching profile-scoped `SessionSummary.cwd`. A dedicated worker performs local `read_dir` and `.gitignore` matching off the UI thread, and responses carry root plus generation identity so a project switch, filter change, or refresh cannot apply stale results. The per-project “Show gitignored files” choice is persisted in `ui-preferences.json`; it bypasses gitignore reads while preserving source-defined transport exclusions. Default filtering uses the nearest `.git` marker, adds ancestor and nested `.gitignore` files through the listed path, and preserves ignored nested repository roots. Double-click opens a dynamic DoofusDock file-preview pane; later previews join its tab group. `FilePreviewStore` reads and decodes content on a worker, rejects binary/oversized text by default, offers an explicit Preview anyway path, and bounds forced text reads to the source's 512 KiB ceiling. Markdown uses the app's cached CommonMark renderer; recognized source files use that renderer's syntax highlighter through a safely chosen code fence. BMP/GIF/JPEG/PNG/WebP images decode to RGBA and SVG vectors rasterize using bounded dimensions before upload to cached egui textures. SVG parsing ignores external image references. PDF pages are individually rasterized by one PDFium 8125 binding confined to the preview worker, then presented as one vertical document with fit-to-pane sizing, 50–300% zoom, page jumps and an eight-page raster cache. A versioned Windows x64 DLL plus its third-party license bundle is copied next to the build output. Preview descriptors use `PersistencePolicy::Never`; `persistent_layout` removes those descriptors and their tree nodes from a cloned document before saving so temporary panes do not leak into restart state. Files and previews remain read-only. HTML, remote filesystem adapters, missing-root fallback, richer context actions, exact Chromium PDF toolbar behavior, exact visual matching and source-paired Windows acceptance remain open requirements.

The opt-in headless agent runner starts at New session for every invocation. Named route fixtures are responsible for constructing their own offline workspace state; the text and image Files-preview fixtures create projects only under the isolated runner profile and wait for asynchronous tree/preview results before rendering.

The Files panel displays the active project folder name and exposes its full root path on hover. A preview pane uses the file basename in Dock chrome rather than repeating a clipped absolute path in its body.

## Typography

JetBrains Mono is the primary application UI typeface; its Medium face is used for heading and button text styles. Fira Code is the egui monospace family and is explicitly used by the Hermes message composer. Both are bundled from official tagged releases with their OFL 1.1 license texts and archive hashes in `assets/fonts/README.md`. The original egui fonts remain fallbacks for uncovered glyphs.

## Transcript Markdown

The transcript delegates CommonMark/GFM parsing and code syntax highlighting to egui_commonmark 0.26 with syntect. Cache state lives on the native app instance. The vendored egui_commonmark backend keeps its upstream package license and changes only the fenced-code copy affordance: a sized, accessible Copy/Copied button replaces a bundled-font-incompatible emoji. A feature-gated automation fixture covers emphasis, links, block quotes, ordered/unordered lists, GFM tables, code highlighting, and the copy control. Streamdown tail repair, rich math/media/artifacts, transcript directives, and source-paired screenshot parity remain open.


### Background prompt ownership

Approval and batch clarification requests are assigned by runtime session ID plus profile to exactly one open native session pane. Prompt state retains that profile, and both human controls and registered semantic actions respond through the same handler using the stored owner scope, even while another pane is selected. Requests with missing/ambiguous ownership or a profile conflicting with the attached gateway endpoint fail closed. Local tests verify routing and UI actions; live authenticated gateway receipts remain unverified.


### Primary tab close behavior

`Ctrl+W` (Command+W on macOS) and agent action `close_active_tab` share one app handler. Closing the selected session tile uses its existing busy confirmation. Closing an occupied primary workspace promotes the nearest valid profile-scoped session tile from the workspace group, or from another Dock zone when the group has none, using canonical DoofusDock close/selection transactions before loading that cached view into primary. If there is no tile, primary returns to a clean New session draft. Blank drafts and full-page routes are no-ops. Other source close precedence, including focused terminal and tool tabs, remains incomplete.


### New session draft reuse

The Sessions-pane New session action fronts the primary New session only when it is empty and matches the attached profile. It can also front a tracked tile only when its pane is open, runtime view is known and idle, message/transcript/composer state is empty, session is unlisted and profile matches. Edited drafts are preserved; creation requests remain single-flight. The native surface does not yet implement Bot Mode owner routes, attachments or debounce-flush synchronization.

Ctrl+W and the semantic close_active_tab action share one close handler. The native target ladder prefers the hovered Dock tab group containing the workspace or a session tile, then the last clicked eligible group, then workspace. A profile-scoped session tile in another Dock group closes via its canonical pane transaction and busy-session confirmation. Egui keyboard traversal does not yet update the focused group, and generic non-session tool-tab closer handoff remains open.
The fixed-source recent-session switcher handles the no-eligible-strip fallback: quick cycling activates the next profile-scoped unarchived session, a held/repeated chord reveals the top-center HUD, Ctrl release commits the highlighted row, and Escape/click-away close it. Debug state exposes pending/open/index/session IDs without changing the human action path. Physical Windows focus/key acceptance remains open.
The Plugins inventory reads and writes the pinned Desktop profile-scoped plugins.manage action=auto_update preference. Unsupported backends leave the checkbox hidden. Supported settings expose auto_apply and the backend check_hours; responses are fenced by request ID and profile.
Agent Plugin Update all sends one profile-scoped `plugins.manage action=update_all` RPC on a separate authenticated WebSocket worker and parses per-plugin result rows into a visible summary. The action shares its typed handler between UI and agent callers, refuses stale inventory/uncertain retries, and refreshes inventory after successful changes. A concurrency fixture holds this RPC open while confirming the primary socket still completes an inventory request. Live authenticated update-all and endpoint-loss behavior remain unverified.
