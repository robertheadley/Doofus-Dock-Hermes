# Hermes Native architecture and ownership

## Current completion boundary

The active user goal is complete, verified support for chat, tool, skill, MCP integration, and plugin functionality from pinned snapshot `8783054ef6cbafd86f10892241436862c1171a66`, measured against the 173-row scope. Feature parity is required; pixel parity is not. The 499-row matrix remains the full source inventory, not the current acceptance denominator. Hermes owns agent/tool execution; the native app owns chat UI and request/state presentation; DoofusDock provides the UI framework. Doofus Hermes is sequenced after scoped parity.

## Messaging route boundary

`GatewayDiscovery::load_messaging_platforms` reads the pinned `/api/messaging/platforms` endpoint. Remote transport carries the configured token/OAuth bearer in headers and profile in the query; local transport uses a one-use gateway ticket. The UI validates bounded platform rows and clears inventory and stale requests on gateway owner changes or disconnect. Enable/disable and metadata-driven configuration updates use the profile-scoped `PUT /api/messaging/platforms/{id}` endpoint and apply only after matching receipts. Config forms keep secret drafts empty, normalize allowlists, support explicit clears, and reload the server schema after a confirmed save. `hot_served` controls live versus restart-required feedback. Pairing reads use `/api/pairing`; approve and revoke use profile-scoped POSTs, require the pinned request/user identifiers, and refresh after confirmation. Pairing data is bounded and profile-fenced; the UI hides empty pairing sections, displays pending counts, and confirms revocation. Telegram QR setup uses start/status/apply/cancel requests with captured profile and pairing ID fencing, remote token/OAuth headers or the local one-use ticket, bounded payload validation, nonblocking status polling, QR rendering, expiry display, deep-link launch, owner-ID allowlist suggestion and explicit apply/cancel controls. Restart-needed results now start `/api/gateway/restart` or monitor the supplied action through profile-scoped `/api/actions/{name}/status`, with bounded retries and visible outcomes. Bot management, localization, live authenticated behavior and source-paired Windows acceptance remain incomplete.

This document applies the Hermes-specific parts of the supplied Doofus Apps Agent Control and Development Architecture. It does not expand this task into implementation work on Doofus Image, Doofus Code, DoofusDock itself, or unrelated apps. No AI model is embedded in Hermes Native.

## Ownership

- **Hermes Python gateway:** authoritative session execution, backend requests, approvals, recovery and backend events. Rust must not recreate agent logic.
- **Hermes Native app core:** owns navigation and view-specific state; feature mutations use the same approved Hermes gateway methods as source UI.
- **egui/eframe host:** owns rendered widgets, accessibility integration and native windows. Hermes Native remains a standalone app when development control is disabled.
- **DoofusDock:** owns canonical `LayoutDocument`, revision-checked layout changes, profiles and presentation. App owns panel content. Logical layout acceptance and physical OS behavior are separate evidence.
- **Semantic control service (in progress):** the initial typed app-action registry is shared by human route/layout controls and the agent protocol; remaining actions, permissions, and feature-level DoofusDock/Hermes operations are still open.
- **Development Debug Bridge (planned):** authenticated local transport for bounded state, semantic actions, events and diagnostics. It is distinct from Hermes gateway and disabled/absent in production.
- **Development supervisor (planned):** declarative reload, Rust rebuild/restart, generation/readiness handshake and automation-client recovery.

## Current boundaries

`src/layout.rs` owns a `DockingService` and `LayoutStore`; projected panel geometry is rendered through DoofusDock presentation APIs. The UI manually renders projected rectangles and accepts titlebar/tab drags that center-tab or edge-split through revision-checked DoofusDock transactions. Center-docked groups render a switchable accessible tab strip, and the headless agent protocol emits bounded primary/secondary pointer and mouse-wheel events through the same egui draw path, and the headless text-field fill uses AccessKit SetValue. The exact pinned egui renderer is vendored with its license and receives a backward-compatible context-menu callback extension; Hermes session tabs map Pin/Unpin and close/bulk-close actions to session/profile-aware app handlers and canonical Dock transactions. Same-group tab reorder uses a revision-checked `ReorderPanel`; source-aligned Ctrl+Tab/Ctrl+Shift+Tab and Ctrl+PageDown/PageUp select profile-scoped main tabs through hover/focus/workspace precedence and canonical `SelectTab`. New sessions append to the existing workspace tab group, and opening a session flattens legacy nested session tabs through canonical `TabPanel` transactions. Split dividers use DoofusDock resize handles and revision-checked `ResizeSplit` transactions. serde_json float_roundtrip preserves DoofusDock split-weight checksums during layout reload. Open new window launches a separate Hermes Native process on the interactive host; each child has a unique persisted LayoutId and UI-preference file while reading shared gateway credentials. Headless agent instances only queue launch requests. `src/native_window.rs` implements a bounded, one-use loopback readiness channel with a 256-bit nonce and versioned receipt; the child reports after its first UI frame. The parent monitors child exit/timeout and only closes a moved source pane after a matching receipt plus a fresh identity/activity/draft check. Moving panes beyond the active session, cross-window session synchronization, physical Windows lifecycle and source-paired acceptance remain open. `src/gateway.rs` owns the Hermes transport. It restores existing sessions, creates a fresh session, submits its initial prompt using the runtime session ID, and forwards basic message lifecycle/delta events. Full-history search uses a separate bounded worker with a profile-scoped native HTTP ticket, keeping it off the WebSocket event actor; requests are loopback-only and disable ambient proxies and redirects. `src/app.rs` owns UI and route state, including stored-session navigation, 200 ms session-search debounce/request fencing, ranked full-history result mapping with loaded local matches, compact `last_active` display and the active runtime ID used to fence incoming events. The active composer exposes a Stop action that calls `session.interrupt` with the active runtime session ID; correlated success preserves partial assistant text and marks it terminal, while an already-idle receipt unblocks the composer. `approval.request` events render accessible cards with only backend-offered once/session/always/deny decisions; `approval.respond` carries the active runtime session and execution generation. Single-question `clarify.request` events render source choices, free text, multi-select answers and skip; `clarify.respond` carries the prompt's active runtime session and generation. Batch server-request `clarify` cards stage all question answers, restore replay answers as editable controls, and send sequential `clarify.lock` RPCs in source order; Skip returns an empty server-request result. Both prompt flows validate correlated receipts and disable controls while offline or pending; local fixtures cover scope, mismatched receipts, stale actions and accessible offline state. Live gateway behavior is unverified. Remaining chat gaps include full source create options/retry, other server-request methods and in-flight request multiplexing, complete event reconciliation, idempotent submit recovery and reconnect. The opt-in `agent-automation` feature builds `hermes-automation`, a headless egui_kittest harness around the same `HermesNativeApp::draw` path. It disables gateway startup, uses an isolated temporary layout profile for success and fallback paths, and removes that profile on exit. This proves semantic widget input and headless frame capture for current UI code, but bypasses the OS windowing host. The default build excludes the runner and its renderer dependency.

The sidebar session-list refresh follows the fixed Hermes snapshot's Desktop `/api/sessions` contract and obtains `last_active` through a fresh native HTTP ticket. It keeps the initial authenticated Gateway `session.list` rows as fallback and carries forward any Gateway-only row after the HTTP result, so a session created during refresh is not discarded. The target source revision is fixed at `8783054ef6cbafd86f10892241436862c1171a66`; implementation batches do not follow later upstream commits.

The session row menu supports Pin/Unpin, persisted unread state, and Archive. These writes share the source's `/mutation-snapshot` compare-and-set contract: read the current revision/generation, mint a separate ticket for PATCH, include the mutation request ID and profile, then update UI state only after a positive receipt. Archive also clears `pinned`; a successful archive moves the row out of active sessions. The archived view pages `/api/profiles/sessions?profile=all&archived=only`, preserves profile ownership when IDs collide, and offers profile-scoped fenced Unarchive. Foreign-profile rows cannot open until the chat lifecycle can carry profile scope across resume, prompt, interrupt and prompt responses. Remote connection aggregation, transient unread events, rename and delete remain open.

## Planned control path

`external agent -> authenticated local bridge -> semantic control service -> app handler -> Hermes gateway or DoofusDock transaction -> structured event/receipt -> screenshot/evidence`.

The current chat event renderer also upserts `tool.start` and `tool.complete` events into transcript groups keyed by tool ID and execution generation. It preserves start arguments and displays bounded completion fields; each row exposes its combined speaker and body through an AccessKit group label. This remains a fixture-backed event slice. It does not yet reconcile out-of-order replay or provide the full upstream tool/reasoning card interactions.

The WebSocket reader recognizes server→client JSON-RPC request frames and returns the upstream `-32601` method-not-found response for methods without handlers, including while another RPC is pending; the original RPC continues. `client.capabilities.server_requests` remains false until the UI can receive, surface and answer supported prompt requests. The fallback does not count as interactive server-request support.

For idle inbound `approval` requests, the actor forwards the request ID and params to the app event loop. The app scopes the card to the uniquely matching runtime/profile session pane, renders only supported backend choices, and returns the selected `{choice}` as the JSON-RPC result on that same request ID. The prompt retains its profile so a response can be sent while another pane is active. Requests without a unique owner are declined. The local actor and AccessKit fixtures cover approval and batch clarify routing, with a separate RPC fixture for ordered `clarify.lock` receipts. Active-session ownership across windows and other server-request methods remain open, so capability negotiation stays disabled.

Session-resume commands carry a generated request ID plus stored session ID and profile. The actor echoes that owner tuple in `SessionResumed`; the UI applies a result only when the same profile-scoped cached view still owns that pending request. Success validates the returned session/profile before hydration; errors latch to that view and expose Retry. Disconnect clears pending ownership, while reconnect allows a fresh resume. Authenticated live recovery, authoritative not-found handling and multiwindow ownership remain open.

## Saved Gateway session owner boundary

Workspace preferences persist secret-free local/remote Gateway descriptors and a selected descriptor ID. Session rows may carry `connection_id`; before the native sidebar opens or mutates such a row, the app resolves it through `SessionOwnerRegistry` and requires the resolved owner to equal the selected descriptor. Untagged legacy rows route through that selected descriptor. Unknown and non-selected tagged owners are refused before dispatch. This is a fail-closed boundary for the current single-`GatewayDiscovery` app, not multi-connection support. `GatewayDiscovery::shutdown` drops its status/event receivers before closing command senders, so queued late events cannot be consumed by the retired UI; its socket actor notices channel closure after the 100 ms read timeout. It does not join/cancel already-running HTTP work or an attach blocked in network setup, and it does not replace the required connection owner on cached state or request/result messages.

Read-only diagnostics have narrower scope than mutating actions. Every mutation validates schema, actor, permission, expected state/layout revision and idempotency key. Asynchronous acceptance is not success; report terminal outcomes. The bridge must not be an arbitrary shell/filesystem proxy or bypass Hermes approval.

## Security and lifecycle

Development control is loopback-only with an unpredictable token or equivalently protected local transport. Authenticate writes, bound schemas/payloads, redact sensitive values, audit decisions, support revocation and keep the feature out of production packages. A supervisor should retain the last working build where possible, report failed builds, prevent stale clients from targeting an old process generation, reconnect to the existing Hermes gateway, and never duplicate active submissions. State survival must be explicit by category; do not claim process-local state survives restart without evidence.

## Evidence layers

1. **Core/protocol contracts:** schemas, permissions, persistence, gateway correlation/idempotency and error paths.
2. **Semantic UI integration:** app UI/control service, accessible queries, user-equivalent actions, receipts and headless screenshots.
3. **Physical Windows host:** actual executable, focus, keyboard/IME, native window moves, docking, DPI, multi-monitor and screenshot parity.

Headless screenshots or accepted commands are not physical-host evidence. Visual and functional parity are tracked separately; both are required.

## Files panel

`files::FileBrowserState` owns transient presentation state: selected root, expanded paths, loaded directory entries, errors, selected row, and the active ignored-file filter. The root is derived from the active route's matching profile-scoped `SessionSummary.cwd`. A dedicated worker performs local `read_dir` and `.gitignore` matching off the UI thread, and responses carry root plus generation identity so a project switch, filter change, or refresh cannot apply stale results. The per-project “Show gitignored files” choice is persisted in `ui-preferences.json`; it bypasses gitignore reads while preserving source-defined transport exclusions. Default filtering uses the nearest `.git` marker, adds ancestor and nested `.gitignore` files through the listed path, and preserves ignored nested repository roots. Activating a file row opens a dynamic DoofusDock file-preview pane; later previews join its tab group. `FilePreviewStore` reads and decodes content on a worker, rejects binary/oversized text by default, offers an explicit Preview anyway path, and bounds forced text reads to the source's 512 KiB ceiling. Markdown uses the app's cached CommonMark renderer; recognized source files use that renderer's syntax highlighter through a safely chosen code fence. BMP/GIF/JPEG/PNG/WebP images decode to RGBA and SVG vectors rasterize using bounded dimensions before upload to cached egui textures. SVG parsing ignores external image references. PDF pages are individually rasterized by one PDFium 8125 binding confined to the preview worker, then presented as one vertical document with fit-to-pane sizing, 50–300% zoom, page jumps and an eight-page raster cache. HTML files expose Source and Preview modes. On Windows, Preview lazily creates a Wry child WebView2 bound to the eframe main window, follows the active Dock pane bounds, hides when the pane is inactive, and opens the canonical local file URL so relative resources and page JavaScript work; top-level navigation is restricted to the selected document and `about:blank`, while relative subresources still load. A versioned Windows x64 PDFium DLL plus its third-party license bundle is copied next to build output. Preview descriptors use `PersistencePolicy::Never`; `persistent_layout` removes those descriptors and their tree nodes from a cloned document before saving so temporary panes do not leak into restart state. Files and previews remain read-only. Remote filesystem adapters, missing-root fallback, richer context actions, exact Chromium PDF toolbar behavior, exact visual matching and source-paired Windows acceptance remain open requirements.

The opt-in headless agent runner starts at New session for every invocation. Named route fixtures are responsible for constructing their own offline workspace state; the text and image Files-preview fixtures create projects only under the isolated runner profile and wait for asynchronous tree/preview results before rendering.

The Files panel displays the active project folder name and exposes its full root path on hover. A preview pane uses the file basename in Dock chrome rather than repeating a clipped absolute path in its body.

### First-run setup surface

`HermesNativeApp::update_gateway_discovery` marks the first-run setup surface available only after the initial gateway attach returns an error. `show_first_run_setup` renders the source-style blocking choice modal on New session. Connect opens a gateway URL form and normalizes HTTP(S) URLs, including scheme-less hosts, like the pinned Desktop. After 500 ms without an edit, `RemoteProbeWorker` sends a credential-free GET to public `/api/status`; OAuth gateways receive a best-effort `/api/auth/providers` request. The worker has an eight-second timeout, disables redirects, caps each JSON response at 512 KiB, and keeps network work off the UI thread. Request IDs discard results for superseded URLs. The UI displays reachability, detected token/OAuth mode, provider names, native-PKCE support and gateway version. Token mode accepts a masked, zeroizing session-token field; its separate worker checks authenticated `/api/status` and the token-query `/api/ws` handshake. For gateways advertising `native_pkce`, a user-triggered worker opens the gateway authorize URL in the system browser, binds a loopback callback on 127.0.0.1, validates state and redeems the authorization code with its PKCE verifier. OAuth Test rotates sessions within 60 seconds of expiry through `/auth/native/refresh`, then uses the current bearer for authenticated `/api/status`, `/api/auth/ws-ticket` and `/api/ws?ticket=...`. Rotated sessions are encrypted with Windows DPAPI and atomically stored in `native-oauth-tokens.json` under the Hermes Native profile directory; the installed Hermes profile is not touched. Passing tests are fenced by request ID and bound to a private hash of the exact normalized URL/auth/credential payload; edits invalidate the Apply gate. remote HTTP-backed APIs beyond the listed coverage and live attach verification, legacy embedded/password-provider login, and local bootstrap remain incomplete. Install reports that the local bootstrap pipeline is not implemented. The opt-in agent runner's `--first-run-setup-fixture` forces this state in a unique temporary offline profile, and `--type-role ROLE NAME TEXT` disambiguates controls that share an accessible name. Diagnostics expose probe/login/test state but never the URL, verifier, tokens or payload fingerprint.

### Primary tab close behavior

`Ctrl+W` (Command+W on macOS) and agent action `close_active_tab` share one app handler. Closing the selected session tile uses its existing busy confirmation. Closing an occupied primary workspace promotes the nearest valid profile-scoped session tile from the workspace group, or from another Dock zone when the group has none, using canonical DoofusDock close/selection transactions before loading that cached view into primary. If there is no tile, primary returns to a clean New session draft. Blank drafts and full-page routes are no-ops. Other source close precedence, including focused terminal and tool tabs, remains incomplete.
