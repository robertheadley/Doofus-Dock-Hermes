Current delivery scope is complete, verified support for chat, tools, skills, MCP integrations, and plugins from pinned Hermes Desktop snapshot `8783054ef6cbafd86f10892241436862c1171a66`, tracked separately in `docs/status/CHAT_TOOL_SCOPE.csv` and `docs/status/CHAT_TOOL_PROGRESS.csv`. Independent native Rust/egui implementation of the stock upstream Hermes Desktop GUI. It uses the Hermes Python gateway as the runtime and DoofusDock for canonical workspace layouts, profiles, docking and presentation.

## Current implementation

The Open new window toolbar control and command-palette action launch a separate Hermes Native process with the current route and profile. On a session route, Move session to new window carries that route/profile and closes its source tab only after a matching one-use receipt confirms the child rendered its first native frame and the source still has no active response or unsent draft. The child uses its own persisted DoofusDock layout and UI preferences while sharing the Hermes Native credential directory. JSON float round-trip parsing preserves checksummed split weights when layouts reload. Automated/headless app instances validate and expose queued requests without launching OS windows; headless tests cover matching receipts, startup failure, timeout, and source-pane rechecks. Backend `sessions.changed` now refreshes the profile session snapshot with request/profile fencing and burst coalescing (PAR-0011 partial). Local peer-window mutation broadcasts, transcript/project reconciliation, focus/reconnect backstops, physical Windows move/close and source-paired behavior remain unverified; see the [completion overview](docs/COMPLETION_OVERVIEW.md).

The tested remote gateway URL now persists in isolated Hermes Native UI preferences. Token-mode credentials and OAuth sessions are encrypted with Windows DPAPI in the isolated credential store. Apply starts a token- or OAuth-authenticated remote WebSocket attach; startup loads a saved URL and matching credential when available. The attach reads runtime identity and the initial session list. Remote HTTP sessions, archives, search, older transcript pages, skills/toolsets, display timestamps, and pin/unread/archive/rename/toolset writes use the saved credential with redirect blocking and gateway-path checks. Expiring OAuth credentials refresh through the Hermes broker and save rotated credentials back to DPAPI. Other remote API surfaces and live remote-service verification remain open.

Tagged session rows are resolved against saved Gateway descriptors before opening a session or sending pin, unread, rename, archive, delete, or export actions. Unknown owners and rows from a different selected connection fail closed. The app still routes through one `GatewayDiscovery`; connection switching, connection-aware session caches and owner-tagged request/result correlation remain open.

After initial gateway discovery fails on New session, the native shell displays a source-style first-run setup card with Connect and Install choices. The remote form normalizes HTTP(S) URLs, including scheme-less hosts, and waits 500 ms after edits before probing public `/api/status`; OAuth gateways also receive an optional public `/api/auth/providers` lookup. These requests send no credentials, are bounded to eight seconds and 512 KiB, disable redirects, and ignore stale URL results. Token mode collects a masked, zeroizing session token and tests authenticated `/api/status` plus `/api/ws` on a worker thread. When the gateway advertises `native_pkce`, OAuth sign-in uses a loopback callback and PKCE state validation. Before OAuth Test, sessions within 60 seconds of expiry are rotated through `/auth/native/refresh`; the rotated bearer is checked against `/api/status` and a single-use WebSocket ticket. OAuth sessions are encrypted with Windows DPAPI in `native-oauth-tokens.json` under Hermes Native's own profile directory, with atomic validated replacement. A passing Test is bound to a private hash of the exact URL/auth/credential payload, and edits revoke Apply eligibility. Apply now attaches using the remote token query or an OAuth WebSocket ticket, identifies the runtime and loads the initial session list; startup loads saved remote credentials. Session/history/search/capability reads and session metadata/toolset writes use remote HTTP authentication. Other remote API surfaces, live service verification, legacy embedded/password-provider login and local Hermes bootstrap remain incomplete, so onboarding parity remains unaccepted. See `docs/BACKLOG.md`.
