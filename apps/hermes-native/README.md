# Hermes Native Rust

Independent native Rust/egui implementation of the stock upstream Hermes Desktop GUI. It uses the Hermes Python gateway as the runtime and DoofusDock for canonical workspace layouts, profiles, docking and presentation.

## Source pins

- Hermes Agent parity snapshot: `8783054ef6cbafd86f10892241436862c1171a66` (downloaded and fixed on 2026-11-14)
- DoofusDock: `f6eb49b9e488f4e851d8d3abe18e95d296201bba`

The source pin and source tree evidence are recorded in `docs/SOURCE_AUDIT.md`. Parity work targets this downloaded snapshot and does not follow later upstream releases unless the target is explicitly changed. The prior Doofus/Hermes prototype remains in the parent workspace and is not part of this crate.

The Sessions sidebar reads the pinned Desktop session-list API with a one-use native HTTP ticket so it can use the same `last_active || started_at` recency rule. The authenticated Gateway session list remains visible if the HTTP read fails.

Session rows expose accessible Pin/Unpin, persisted Mark unread/Mark read, and Archive actions. Writes use the pinned Desktop mutation-snapshot revision and generation, separate one-use tickets for the read and PATCH, and update visible state only after a confirmed receipt. The Sessions pane pages `/api/profiles/sessions?profile=all&archived=only`, keeps same-ID rows distinct by profile, shows profile ownership, and exposes profile-scoped Unarchive. Rows from another profile open in profile-scoped Dock panes; live cross-profile acceptance remains open. Archived search filters loaded rows locally. Agent locators include profile-scoped IDs where needed. The query and mutation are fixture-tested; live-profile behavior remains open.

## Current implementation

The native shell provides DoofusDock-backed layout profiles, route classification, authenticated gateway attach, session listing/transcript restore, and an opt-in headless AccessKit agent runner. Dynamic session panes render their profile-scoped transcript, history action and composer in canonical Dock tiles; existing sessions front their tile, blank sessions start unlisted, and an admitted first prompt adds the session to the sidebar. Active session tabs require confirmation to close and leave Hermes running. Ctrl+Tab/Ctrl+Shift+Tab and Ctrl+PageDown/PageUp cycle profile-scoped session tabs with wraparound. If no eligible tab strip exists, a quick chord jumps to the next recent session; holding or repeating the chord opens a compact, accessible switcher, and releasing Ctrl commits its selection. Opening sessions appends to the workspace tab group and repairs legacy nested groups. Background message/tool events and submission receipts update the matching cached view. Resume outcomes now use correlated request/session/profile receipts: stale responses are ignored, errors remain on their owning pane with an accessible Retry action even when cached history exists, and successful transcripts hydrate only a matching profile/session view. The cache is in-memory and targets 32 idle sessions; durable scroll remains incomplete. New session fronts only an empty profile-matching main draft or a known idle, empty, unlisted same-profile tile; typed/edited drafts remain in place. Primary-pane promote/reset and active-group targeting follow `Ctrl+W` and agent `close_active_tab`. Bot Mode owner-route/attachment-aware draft semantics, authoritative not-found recovery and full close-target precedence remain incomplete. Egui keyboard focus traversal and generic tool-tab handoff remain incomplete. The rest of the Hermes Desktop workflow remains incomplete. The runner can inspect controls, click/type by accessible name, and save screenshots without opening a native window or starting Hermes; it uses and cleans a temporary isolated layout profile. `--session-pane-fixture` captures a deterministic dynamic-tab view; `--recent-session-switcher-fixture` captures the switcher over three synthetic sessions. Plain captures start at the offline New session route, so use route actions or a named fixture to capture a different state. Its optional `--stdio` child process protocol adds versioned, bounded NDJSON health/state/tree/diagnostic reads, semantic click/right-click/type/select/keypress/drag actions, wait-for-visible-control, generation-checked action receipts, idempotent retry handling, and screenshot capture. The default build excludes the runner and its renderer dependency.

Titlebar drags can center-tab or edge-split panels through canonical DoofusDock transactions. Dock tab groups render accessible switchable tabs; Ctrl+Tab/Ctrl+Shift+Tab and Ctrl+PageDown/PageUp cycle the main group through the source hover/focus/workspace ladder. `actions.right_click`, semantic `actions.scroll` and exact-value `actions.fill`, modified `actions.keypress`, and `actions.drag` drive real egui wheel and secondary/primary pointer events from an accessible source to either an accessible destination or a bounded coordinate, including same-group tab reorder through `ReorderPanel`. Split resize handles preview bounded adjacent weights and commit through DoofusDock on release. A versioned typed app-action registry shares navigation and layout handlers between first-party UI controls and the agent protocol; extension to all app/DoofusDock/Hermes operations is incomplete. The authenticated bridge, rebuild/restart supervisor, full chat workflow, source-complete widgets, physical Windows behavior, and paired upstream/target acceptance evidence remain incomplete. This is not a 1:1 replacement yet. See [architecture](docs/ARCHITECTURE.md), [agent automation](docs/AGENT_AUTOMATION.md), [protocol](docs/AGENT_AUTOMATION_PROTOCOL.md), and [control crosswalk](docs/AGENT_CONTROL_CROSSWALK.md).

The active transcript uses egui_commonmark 0.26 with pulldown-cmark and syntect for CommonMark/GFM structures, links, tables, and highlighted fenced code. The feature-gated agent runner can load an isolated Markdown fixture for screenshots. Streaming-specific repairs, math/media plugins, transcript directives, artifact conversion, and matched source visual verification remain open.

The DoofusDock Files panel now reads the selected session's project `cwd` from Hermes' pinned session-list API and displays a lazy, asynchronous, read-only directory tree. It sorts folders before files, bounds each listing to 1,000 entries, excludes the pinned Desktop's transport/build-noise names, exposes retry for unreadable folders, and discards results from a previous project or refresh generation. This is an initial local-filesystem slice: remote connection routing, gitignore filtering and its show-ignored preference, folder fallback, file previews/open-in-pane, context actions, source-matched chrome, and paired Windows acceptance remain open. It does not modify files.

The transcript keeps message roles visible and supports local per-message timestamps. The selected Hermes profile's `display.timestamps` config is read through authenticated `/api/config`; `/timestamps` toggles timestamps and `/timestamps on|off|status` selects or reports a window-only override. The config defaults off, labels use local millisecond time, and commands never go to the model as prompt text. The `--transcript-timestamps-fixture` option captures the distinct timestamp-on surface. Exact source locale/tooltip formatting, tool-run lifecycle stamps, and source-paired Windows verification remain open.

## Run on Windows

```powershell
cargo run
```

The DoofusDock layout document is saved under `%APPDATA%\HermesNative\layouts`. Set `HERMES_NATIVE_PROFILE_DIR` to an isolated directory for acceptance runs.

Run a headless agent navigation and screenshot capture without opening a window:

```powershell
cargo run --features agent-automation --bin hermes-automation -- --inspect --click Files --screenshot artifacts\agent-ui\files-panel.png
```

Start a persistent agent-controlled child process using inherited stdin/stdout:

```powershell
cargo run --features agent-automation --bin hermes-automation -- --stdio
```

See [the protocol contract](docs/AGENT_AUTOMATION_PROTOCOL.md) for NDJSON methods, bounds and retry behavior.

Use `--viewport 1440x900` to set the capture dimensions. This harness is semantic UI evidence; it does not prove physical Windows window behavior.

The Capabilities route now exposes source-style Skills, Plugins, Connectors and Toolsets tabs. Skills and Toolsets load from the current Hermes gateway's profile-scoped API with local search. Toolsets can be enabled or disabled through the upstream PUT endpoint, with optimistic UI state, serialized HTTP writes, and rollback when the request or receipt fails. Plugins fetch the pinned Desktop public JSON feed off-thread, merge profile-installed Agent Plugins into catalog matches, append installed-only rows, and render searchable 60-row pages. Tier/category/tag facets, installed/update filters and stars/newest/updated sorting follow the pinned catalog query rules. The route also reads the profile-scoped installed Agent Plugin inventory, applies source hidden-plugin rules, shows version/source/status/update metadata, toggles by canonical key, and offers confirmed user/git uninstall through shared UI/agent handlers with correlated gateway receipts. The live agent UI previously loaded 2,378 public catalog entries without starting the Hermes gateway. Connectors read the profile-bound list/catalog/accounts and display source-style status segments, ordering, and name/slug search. Curated Agent Plugin installation now uses source inspection, explicit reviewed-SHA confirmation, and a profile-scoped receipt. Catalog updates, Desktop plugin runtime/settings, connector sign-in, local MCP, tool/policy editing and live profile acceptance remain incomplete. Isolated WebSocket and AccessKit fixtures cover plugin management and filter/merge behavior; the visible inventory remains synthetic.

Uninstalled catalog entries can now be inspected through the selected Hermes profile and installed as Agent Plugins only after a review dialog shows the repository, reviewed commit, component type and warnings. The RPC is pinned to that inspected SHA and profile; insecure sources, non-Agent entries and pin mismatches fail closed. A successful correlated receipt refreshes the installed list. Installed Agent Plugins with updates now have a shared UI/agent update action; capability changes require explicit consent, caution scans require an explicit override, and dangerous scans cannot be overridden. Desktop-half reconciliation, custom repositories and live-profile acceptance remain incomplete. The `--plugin-install-review-fixture` and `--plugin-update-scan-review-fixture` options capture synthetic review states without starting a gateway.

Typography uses bundled JetBrains Mono for the application UI and Fira Code for monospaced content, including the message composer. Both typefaces include their OFL 1.1 license text and source/release metadata under `assets/fonts/`; see [font sources](assets/fonts/README.md). During an active response, the composer exposes an accessible Stop action that calls the upstream `session.interrupt` RPC with the active runtime session ID. It handles both `interrupted` and `not_interrupted` receipts and keeps interrupted partial text in the transcript. Canonical `approval.request` events show accessible cards with only choices offered by Hermes; decisions use generation-scoped `approval.respond`. Single-question `clarify.request` events support source choices, free text, multi-select answers and skip through generation-scoped `clarify.respond`. Batch `clarify` server requests render an editable multi-question card; Confirm sends per-question `clarify.lock` RPCs sequentially, replayed answers are staged for editing, and Skip cancels the request with an empty result. Current-session `tool.start` and `tool.complete` events render generation-scoped transcript groups with bounded completion output and a combined AccessKit label; local event/UI fixtures cover reused tool IDs and rendered content. The idle gateway actor routes inbound `approval` and batch `clarify` requests into active-session cards; batch answers use ordered `clarify.lock` calls. The client keeps server-request support disabled while other handlers, pending-RPC multiplexing and request ownership remain incomplete. Unknown methods receive `-32601` and an in-flight RPC continues. These fixtures do not verify live gateway behavior or full interactive request negotiation.

The Plugins inventory also reads and writes the pinned source's profile-scoped automatic-update preference. The accessible checkbox is hidden if Hermes lacks `plugins.manage auto_update`. Its synthetic 1440×900 fixture uses `--plugin-auto-update-fixture` and starts no gateway.
The Agent Plugins inventory supports profile-scoped Update all through the shared human/agent action. Results show updated, current, failed, and review-required plugins; review-required items are never consented automatically. A separate authenticated connection keeps this operation isolated from other gateway requests (up to ten minutes). The `--plugin-update-all-report-fixture` automation mode captures a distinct synthetic expanded result state without a gateway.
