## Intended boundaries

The planned app is a Rust + egui client. The Hermes gateway remains responsible for conversations, tools, models, sessions, and approvals. Hermes-Doofus remains responsible for tasks, plans, requirements, evidence, vault data, and routing decisions. DoofusDock owns only workspace composition. Rust reducers and transport adapters will translate typed messages into views; widgets will not make backend decisions.

The app uses the DoofusDock crates at pinned revision `f6eb49b9e488f4e851d8d3abe18e95d296201bba`. The source checkouts were dirty at review time, so they are not path dependencies and their existing edits were left untouched.

### Secure vault code and saved-login requests

The Gateway actor accepts pinned `secret`, `vault.code`, and `vault.save_login` server requests and keeps each response on the originating connection/profile. Secret prompt cards show only the requested environment variable and prompt text; metadata is not rendered. Native secret drafts use zeroizing strings and masked controls; accessibility labels and diagnostics omit entered values, and route/owner changes clear the draft and egui undo history. If a write outcome is unknown, the app clears secret material and blocks same-request replay from resending it. Headless UI and same-socket actor tests cover these paths; authenticated Gateway and packaged Windows behavior remain unverified. These remain separate from `vault.unlock_prompt`.

### Background prompt ownership

Approval and batch clarification requests are assigned by runtime session ID plus profile to exactly one open native session pane. Prompt state retains that profile, and both human controls and registered semantic actions respond through the same handler using the stored owner scope, even while another pane is selected. Requests with missing/ambiguous ownership or a profile conflicting with the attached gateway endpoint fail closed. Local tests verify routing and UI actions; live authenticated gateway receipts remain unverified.
The fixed-source recent-session switcher handles the no-eligible-strip fallback: quick cycling activates the next profile-scoped unarchived session, a held/repeated chord reveals the top-center HUD, Ctrl release commits the highlighted row, and Escape/click-away close it. Debug state exposes pending/open/index/session IDs without changing the human action path. Physical Windows focus/key acceptance remains open.
