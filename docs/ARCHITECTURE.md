# Hermes DoofusDock architecture

## Current implementation

- `doofusdock-core::LayoutDocument` is the only persisted owner of panel IDs and geometry.
- `DockingService` validates revision-bound panel-center operations.
- `doofusdock-presentation::project` derives the visible panel rectangles from the canonical document.
- `LayoutStore` performs bounded, atomic layout persistence.
- The egui host renders app-owned panel content; the Rust application owns its content and navigation.
- Hermes runtime and Gateway remain authoritative for conversations and capabilities. `gateway.rs` connects over the Hermes gateway protocol and maps typed session, prompt, approval, clarification and capability operations into app events. The authenticated Doofus bridge is not connected yet.
- Session identity is profile plus stored session ID when a profile is known. The active chat carries that profile through resume, prompt submission, interruption, approvals and clarification RPCs. Session IDs that collide across profiles remain separate in the list. The registered `open_session` action accepts both identity fields; path-only navigation rejects ambiguous IDs.
- The isolated agent UI process exposes versioned commands over inherited stdio. Registered actions run through the application handler, advance the egui frame, and then return state; screenshots render that updated frame. This headless process has no Hermes gateway connection, so it verifies the UI control surface rather than live backend behavior.
- Active runtime session renames fetch the current revision with profile-scoped `session.resume`, then send `session.mutate` with `operation: rename`, the runtime ID, revision, and request ID. An uncertain reply retains the exact mutation tuple in the current gateway actor; the dialog can retry that tuple without a fresh snapshot. After reconnect, an exact retry is unavailable and stops before sending a new mutation. Other stored sessions use the gateway's profile-scoped HTTP mutation snapshot and a fresh one-use ticket for the PATCH. A confirmed response title is required before the sidebar, archived list, and search results update. Authenticated live runtime behavior and cross-reconnect recovery remain to be verified.
- Prompt submission carries the UI's stable `submission_id` and validates the canonical receipt's `admission_id`, status, and session destination. Pending sends are keyed by profile plus runtime session, so each open chat can retain its own identity and retry state. An uncertain RPC reply preserves the optimistic transcript row and exposes an agent-accessible retry using the same ID. Completion settles only the matching admission, including when completion arrives before the RPC receipt. An `unknown` receipt triggers profile-scoped `prompt.resolve_unknown` with the admission ID and execution generation. Durable retry state across app restart and replay of background-session transcript events remain incomplete.

The initial tree uses four zones: files/tasks on the left, chat in the center, preview/Doofus on the right, and terminal/tests/logs at the bottom. The layout can form tab groups through panel drag and drop. Floating windows, split resizing, tab selection, hide/close behavior, and profile switching are not implemented in this slice.

## Intended boundaries

The planned app is a Rust + egui client. The Hermes gateway remains responsible for conversations, tools, models, sessions, and approvals. Hermes-Doofus remains responsible for tasks, plans, requirements, evidence, vault data, and routing decisions. DoofusDock owns only workspace composition. Rust reducers and transport adapters will translate typed messages into views; widgets will not make backend decisions.

The app uses the DoofusDock crates at pinned revision `f6eb49b9e488f4e851d8d3abe18e95d296201bba`. The source checkouts were dirty at review time, so they are not path dependencies and their existing edits were left untouched.

## Compatibility and evidence

The Hermes Desktop Plugin SDK is JavaScript/React; DoofusDock extensions are Rust contracts. Existing plugins are not automatically compatible. A sandboxed compatibility path or per-plugin native migration decision remains open. The preserved package contains 565 research rows: 499 stock Hermes Desktop requirements are in scope and 66 Hermes-Doofus requirements are excluded. Capability states are not promoted without current evidence.

- The canonical Dock supports profile-scoped session pane descriptors. Hermes Native vendors only the exact pinned DoofusDock egui renderer with its license and a backward-compatible context-menu callback; session-tab close/bulk-close and Pin/Unpin actions map into the canonical Dock and profile-aware Hermes handlers. Its headless agent can emit secondary-pointer input to open those same menus. Each visible tile temporarily renders its own keyed transcript, composer, paging state and visible approval/clarify cards, then restores the primary chat state. Existing sessions and deep links front canonical tiles; blank sessions create unlisted tiles and first admitted prompts add them to the sidebar. Hidden submission receipts route to the matching cached view. Resume request IDs, stored session IDs and profiles travel through the gateway actor; only a matching pending receipt can hydrate a view, and resume errors with Retry remain local to the tile. The 32-view cache remains in-memory and persistent scroll remains open. Approval and batch clarification requests route to their unique profile-scoped pane, including semantic response actions while hidden; authenticated live receipts remain unverified. See [Hermes Native PLAN.md](../apps/hermes-native/docs/PLAN.md), revision 52.
- The session tab strip is the canonical DoofusDock tab group and exposes close controls for session tiles. Opening another session appends to that group; legacy nested session groups are flattened with canonical `TabPanel` operations on session open. Ctrl+Tab/Ctrl+Shift+Tab and Ctrl+PageDown/PageUp use the source hover/focus/workspace ladder and select profile-scoped tabs with canonical `SelectTab`. Closing an active tile asks for confirmation and closes the pane without interrupting Hermes. The primary workspace pane remains a separate tab; Close targeting first checks the hovered eligible session tab group, then the last clicked eligible group, then workspace. `Ctrl+W` and agent `close_active_tab` promote the nearest profile-scoped session tile into primary or reset an occupied primary chat to New session. Closed session tiles are remembered in a bounded, in-memory LIFO stack per profile; Ctrl+Shift+T (macOS: Command+Ctrl+Shift+T) and agent `restore_closed_session_tab` reopen and focus the last eligible tile through DoofusDock. Closing the selected tile moves the primary route to the adjacent selected session or New session while preserving the profile. Background server requests also route to their unique profile-scoped pane. Bot Mode owner-route draft reuse and attachment-aware drafts remain open; edited drafts are deliberately preserved instead of reused. Close-target precedence across tool zones and complete keyboard/focus/overflow behavior also remain open.
- The active transcript uses egui_commonmark with GitHub-style tables/task lists and syntect highlighting. A small vendored backend change replaces an unsupported emoji copy glyph with a sized, accessible Copy/Copied button. Stored transcripts can fetch older 120-message pages with profile and latest-order validation; app state rejects stale replies and merges page overlap safely. This is not the source's virtualized scroll window or retention behavior, and live gateway acceptance remains open. Streamdown streaming repair, media, math plugins, transcript directives, rich artifacts/cards, and exact source typography are still incomplete.
- Transcript find-in-page opens with Ctrl+F (macOS Command+F), matches loaded message text and speaker labels case-insensitively, shows a result count, steps with buttons/Enter and Ctrl+G (macOS Command+G), and closes with Escape. The selected message card is highlighted and scrolled into view. It currently searches loaded transcript rows and does not highlight individual text spans or other rendered panes; full source parity remains open. Its distinct synthetic 1440×900 review capture is `artifacts/agent-ui/transcript-find-in-page-20261115.png`.


### Background prompt ownership

Approval and batch clarification requests are assigned by runtime session ID plus profile to exactly one open native session pane. Prompt state retains that profile, and both human controls and registered semantic actions respond through the same handler using the stored owner scope, even while another pane is selected. Requests with missing/ambiguous ownership or a profile conflicting with the attached gateway endpoint fail closed. Local tests verify routing and UI actions; live authenticated gateway receipts remain unverified.
The fixed-source recent-session switcher handles the no-eligible-strip fallback: quick cycling activates the next profile-scoped unarchived session, a held/repeated chord reveals the top-center HUD, Ctrl release commits the highlighted row, and Escape/click-away close it. Debug state exposes pending/open/index/session IDs without changing the human action path. Physical Windows focus/key acceptance remains open.

## Hermes Native plugin catalog

The Plugins route reads the pinned Desktop's public JSON endpoint without a gateway ticket and without blocking egui. A single worker, request correlation, bounded response size, redirect limit and error state keep loading controlled. Parsed entries retain the Desktop's catalog search fields, malformed-name fallback, tier+identifier replacement rule, stars and date signals. Profile-installed Agent Plugins merge by catalog name and unmatched rows append; trust tier, category, tags, installed/update-only facets and stars/newest/updated sort follow the pinned catalog query behavior. Agent Plugin list, canonical-key toggles, confirmed user/git removals and reviewed curated catalog installs use profile-scoped `plugins.manage` actor calls with correlated receipts; disconnect after a mutation is an unknown outcome. WebSocket and AccessKit fixtures cover list/toggle/remove/install and filter/merge behavior. Desktop plugin runtime state/package control, catalog updates and live profile validation remain open.

Uninstalled curated entries use a shared UI/agent install request: Hermes inspects the source first, the review window presents the catalog identity, repository, full commit SHA, component type and warnings, then explicit confirmation submits `plugins.manage install` with the same catalog name, profile and inspected SHA. Insecure/non-Agent sources and catalog pin mismatch are rejected; a checked receipt refreshes the profile inventory and exposes missing environment/warnings. A timeout/disconnect is treated as unknown and never replayed automatically. The present flow installs only the Agent component; Desktop half, custom-repository, update and live-profile parity remain open.

Installed Agent Plugin updates now use the pinned Desktop's `plugins.manage action=update` flow. Capability-widening deltas require explicit acceptance; scan findings are shown in severity order, caution may proceed only through a visible force confirmation, and dangerous scans cannot be overridden. Each response is fenced by request/name/profile and the accepted options. This does not yet reconcile Desktop plugin halves or prove a live update against the installed Hermes profile.

The current Connectors read slice uses the active profile-bound gateway actor for the pinned Desktop's `connectors.list`, `connectors.catalog` and `connectors.accounts` methods. Responses are correlated to the selected Connectors tab, catalog entries are unioned with list-only slugs, and source title/status fallbacks feed searchable connection rows and account details. The native directory derives All/Connected/Available/Off segments, orders status groups and rows by the pinned Desktop's state priority, and searches names/slugs. Isolated WebSocket and AccessKit fixtures cover the read contract and directory behavior. Mutating authentication/connect, local MCP configuration, tools/policy and hosted account flows remain unimplemented and live profile behavior is unverified.
The Plugins inventory reads and writes the pinned Desktop profile-scoped plugins.manage action=auto_update preference. Unsupported backends leave the checkbox hidden. Supported settings expose auto_apply and the backend check_hours; responses are fenced by request ID and profile.
The Hermes Native Plugins surface now includes profile-scoped Agent Plugin Update all with typed `updated/current/failed/needs_review` rows, explicit review preservation, uncertain-result fencing, and post-update inventory refresh. The long-running RPC uses a separate authenticated connection so it does not block requests on the primary gateway actor; a concurrency fixture verifies the two operations independently.
